# Конспект: TypeScript и React

Краткие заметки по темам, изученным в упражнениях из [`self-study/typescript`](../../../self-study/typescript/). Здесь собраны понятия и методы, которые встречались в заданиях, и их практическое назначение.

## TypeScript

### Типы и модели данных

- **`interface`** описывает форму объекта: его поля и типы. Использовался для сообщений, задач, пользовательских настроек и состояния.
- **Объединение (`A | B`)** задаёт несколько допустимых вариантов значения. Например, сообщение может быть текстовым или содержать фотографию.
- **Пересечение (`A & B`)** объединяет поля нескольких типов. Подходит, когда объект должен соответствовать нескольким наборам требований одновременно.
- **Сужение типа** уточняет тип внутри ветки кода. Проверки `'text' in message`, `response.success` и `instanceof Error` помогают безопасно обратиться к свойствам конкретного варианта.
- **Дискриминирующее поле** — общее поле с разными литеральными значениями, например `status: 'loading' | 'success' | 'error'`. По нему TypeScript понимает, какие данные доступны в каждом состоянии.
- **`enum` и `never`** применялись для перечисления состояний интерфейса и проверки полноты `switch`: компилятор может обнаружить новый вариант, для которого забыли написать обработчик.

### Generics и служебные типы

- **Generics (`<T>`)** позволяют писать повторно используемый код, сохраняя конкретный тип данных. Они использовались в API-ответах, HTTP-клиенте, Store и асинхронном загрузчике.
- **`Partial<T>`** делает все поля типа необязательными. Это удобно для передачи частичного обновления настроек или состояния.
- **`Readonly<T>`** запрещает менять свойства через типизированную ссылку. Это ограничение проверки типов, а не глубокая блокировка объекта во время выполнения.
- **`import type`** импортирует только тип. Такой синтаксис важен при включённом `verbatimModuleSyntax` и не создаёт runtime-импорт.

### DOM и события

- **`document.querySelector<ElementType>()`** задаёт ожидаемый тип найденного элемента. Результат всё равно может быть `null`, поэтому перед использованием нужна проверка.
- **`addEventListener()`** подписывает функцию на событие элемента. Тип события (`MouseEvent`, `PointerEvent`) даёт типизированный доступ к его данным.
- **Делегирование событий** позволяет обработать клики по динамическим дочерним элементам одним слушателем на родителе. `event.target`, `instanceof HTMLElement` и `closest()` помогают определить, по какому элементу кликнули.
- **`classList`, `textContent`, `remove()`** используются для изменения классов, текста и удаления DOM-элементов.

### Классы и управление состоянием

- **Модификаторы `public` и `private`** задают доступность полей и методов класса.
- **`clamp()`** ограничивает число диапазоном. Пригодился для ограничения координат перемещаемого элемента.
- **Pointer Events** (`pointerdown`, `pointermove`, `pointerup`, `pointercancel`) позволяют реализовать перетаскивание мышью, пером и касанием. `setPointerCapture()` удерживает поток событий на нужном элементе.
- **Store и подписки** показывают базовую модель управления состоянием: `getState()` читает состояние, `update()` создаёт обновлённое значение, `subscribe()` сообщает подписчикам об изменении и возвращает функцию отписки.

### Запросы и асинхронность

- **`Promise<T>` и `async/await`** описывают асинхронные операции и тип результата.
- **`fetch()` и проверка `response.ok`** используются для выполнения HTTP-запроса и обработки неуспешного ответа.
- **`try/catch/finally`** разделяет успешную обработку, ошибку и действия, которые должны выполниться в любом случае, например завершение индикатора загрузки.
- **Generic HTTP-методы** позволяют передать тип ожидаемого JSON-ответа. Это подсказка компилятору, но не проверка данных во время выполнения; полученный от сервера JSON при необходимости нужно валидировать отдельно.
- **Union состояний загрузки** (`idle`, `loading`, `success`, `error`) не даёт смешивать данные и ошибку в одном состоянии.

### Работа с внешним SDK

- **`declare global` и расширение `Window`** описывают дополнительные свойства браузерного объекта, например `window.Telegram`.
- **Optional chaining (`?.`) и nullish coalescing (`??`)** безопасно читают необязательные данные и задают запасное значение.
- **Обёртка над SDK** отделяет проверку доступности Telegram WebApp и получение пользователя от кода, который использует SDK.

## React

### Компоненты, props и события

- **Функциональный компонент** возвращает JSX и описывает часть интерфейса. Компонент одной задачи получает данные и callback-функции через `props`.
- **Типизация props** фиксирует обязательные данные компонента и сигнатуры обработчиков, например `(id: number) => void`.
- **`key` в списках** помогает React сопоставлять элементы между рендерами; для задач используется их идентификатор.
- **Обработка формы** обычно начинается с `event.preventDefault()`, чтобы браузер не перезагрузил страницу. `trim()` отсекает пустые строки и лишние пробелы.

### Состояние и обновление интерфейса

- **`useState`** хранит данные, изменение которых должно вызвать новый рендер: текст поля, задачи или выбранный фильтр.
- **Иммутабельность** означает создание нового массива или объекта вместо изменения старого. `map()` обновляет выбранную задачу, `filter()` удаляет её или отбирает нужные, spread (`...`) копирует и дополняет значение.
- **Фильтрация списка** вычисляет видимые задачи по выбранному значению (`all`, `active`, `completed`). Это производное значение, которое строится из списка и фильтра.
- **`useReducer`** полезен, когда переходов состояния много или они образуют набор действий. В Todo используются `ADD_TASK`, `TOGGLE_TASK`, `DELETE_TASK` и `SET_FILTER`; reducer возвращает новое состояние для каждого действия.

### Эффекты, ссылки и сохранение

- **`useEffect`** выполняет побочные действия после рендера: например, устанавливает фокус или синхронизирует состояние с внешним хранилищем. Массив зависимостей задаёт, при каких изменениях запускать эффект.
- **`useRef`** хранит ссылку на DOM-элемент между рендерами, не вызывая новый рендер при изменении ссылки. `useRef<HTMLInputElement>(null)` используется для фокуса на поле ввода.
- **`localStorage`** сохраняет данные в браузере между перезагрузками страницы. `JSON.stringify()` сериализует значение, `JSON.parse()` восстанавливает его.
- **Кастомный хук `useLocalStorage<T>`** объединяет состояние React с чтением и записью в `localStorage`; generic-параметр позволяет повторно использовать хук для разных типов данных.

### Общее состояние и повторные рендеры

- **Context (`createContext`, `Provider`, `useContext`)** передаёт общее состояние и команды компонентам без промежуточной передачи props через каждый уровень.
- **Кастомный хук `useTodo()`** скрывает детали получения контекста и может проверить, что компонент используется внутри Provider.
- **`React.memo`** пропускает повторный рендер компонента, если его props не изменились при поверхностном сравнении.
- **`useMemo`** запоминает результат вычисления, например отфильтрованный массив, пока не поменялись зависимости.
- **`useCallback`** запоминает ссылку на функцию между рендерами. Это может быть полезно, если функцию получает компонент, обёрнутый в `React.memo`.

Мемоизация не нужна автоматически везде: она полезна при дорогих вычислениях или когда стабильность ссылок действительно предотвращает лишние рендеры. В текущем варианте Todo используется `React.memo`; `useMemo` и `useCallback` из задания по оптимизации в рабочем коде пока не применены.

## Главное

TypeScript помогает описывать данные и находить несоответствия до запуска, но не проверяет автоматически JSON от сервера. React обновляет интерфейс в ответ на состояние; поэтому состояние следует обновлять иммутабельно, а побочные действия выполнять в эффектах. Хуки, generics и компоненты лучше выбирать под конкретную задачу, а не добавлять без необходимости.
